# Contributing Guidelines

Thank you for taking the time to review this repository. It is primarily a personal archive of C++ coursework, exercises, and experiments, so external contributions are not generally expected. These guidelines explain how to share feedback or propose a correction.

## Reporting an issue or suggesting an improvement

- Explain clearly which source file or exercise is involved.
- Describe the problem or suggestion, including the compiler and operating system if they are relevant.
- For a suspected bug, include the steps needed to reproduce it and the observed behavior. Do not include private information.
- For a general question or informal suggestion, contact the repository owner directly.

## Proposing a code change

Please contact the repository owner before spending time on a substantial change or opening a pull request. If a change is agreed upon, keep it focused and explain its purpose. Preserve the educational context of the original exercise, and avoid unrelated formatting or refactoring changes.

For C++ examples, use descriptive names where appropriate and compile the affected source file with warnings enabled. For example:

```bash
g++ -std=c++17 -Wall -Wextra path/to/example.cpp -o example
```

Some exercises may depend on a specific assignment or learning context. A proposed correction should explain the expected behavior and, where possible, include a concise way to verify it.
